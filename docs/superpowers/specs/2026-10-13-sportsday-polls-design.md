# 명량운동회 플랫폼: 4단계(투표) 설계

- 작성일: 2026-10-13
- 상태: 사용자 검토 대기
- 선행: 1단계 `2026-10-11-sportsday-foundation-design.md`, 2단계 `2026-10-12-sportsday-team-draw-design.md`, 3단계 `2026-10-12-sportsday-manito-design.md`. 이 문서에 없는 규칙(인증, 세션, 에러 처리, 디자인 시스템, 관리 화면 레이아웃)은 앞 단계 스펙과 현재 코드를 따른다

## 0. 목표와 확정된 요구사항

생성자가 운동회 중에 투표를 열고, 참가자가 자기 폰으로 투표하며, 생성자가 마감 후 결과를 공개한다.

1단계에서 정한 것: 익명/비익명, 다중 선택(최대 선택 수), 기타 직접 입력, 상태 `open | closed | revealed`, 테이블 `polls`, `poll_options`, `poll_voters`, `poll_answers`.

사용자가 이번에 확정한 내용:

- 결과는 **생성자가 공개할 때** 모두에게 보인다
- 참가자는 **마감 전까지 투표를 바꿀 수 있다**
- 공개 전 생성자는 **투표 인원과 아직 안 한 사람 명단**만 본다. 득표는 보지 않는다
- 폴링 없음. 화면은 접속·새로고침 시점의 상태를 보여 준다

## 1. 상태와 흐름

| 상태 | 참가자 | 생성자가 할 수 있는 일 |
|---|---|---|
| `open` 진행 중 | 투표, 다시 투표 | 마감, 수정(투표자 0명일 때), 삭제 |
| `closed` 마감 | 내 선택만 봄 | 다시 열기(→`open`), 결과 공개(→`revealed`), 수정(투표자 0명일 때), 삭제 |
| `revealed` 결과 공개 | 결과를 봄 | 삭제 |

- 만들면 바로 `open`이다. 한 운동회에 투표를 여러 개 동시에 열 수 있다
- `revealed`는 되돌릴 수 없다. 공개는 `closed`에서만 할 수 있다
- 삭제는 확인 문구 `삭제`(앞뒤 공백 무시)를 입력해야 한다
- 운동회 `status`(준비중·진행중·종료)는 투표에 영향을 주지 않는다

## 2. 투표 규칙

- **만들기·수정 입력**: 제목 1~50자, 항목 2~20개(각 1~50자, 빈 줄은 무시, 같은 이름 중복 불가), 익명 여부(기본 익명), 최대 선택 수 1~항목 수, 기타 허용 여부(기본 아님)
- **수정**: 투표자가 0명이고 `revealed`가 아닐 때만. 항목을 통째로 바꾼다
- **투표 입력**: 고른 항목 id 목록과 기타 내용. 항목 id는 그 투표의 항목이어야 하고 중복은 하나로 친다. 기타 내용은 앞뒤 공백을 지우고 1~50자일 때만 한 개로 센다(빈 칸이면 무시). 기타는 허용된 투표에서만 받는다
- **개수**: 항목 + 기타 합이 1개 이상, 최대 선택 수 이하
- **다시 투표**: `open`일 때만. 같은 트랜잭션에서 이전 응답을 지우고 새로 넣는다. `poll_voters.voted_at`을 갱신한다
- 투표는 출석·결석과 관계없이 운동회의 모든 참가자가 할 수 있다
- 참가자를 삭제하면 그 사람의 투표 기록과 응답도 함께 지워진다(`ON DELETE CASCADE`)

## 3. 익명과 비공개

- 다시 투표를 위해 `poll_answers.participant_id`는 익명 투표에서도 저장한다. **익명은 "화면과 응답에 이름이 나오지 않는다"는 뜻**이며 생성자·관리자도 이름을 볼 수 없다
- 득표(항목별 수, 기타 내용)는 `revealed` 전에는 누구에게도 반환하지 않는다(생성자 포함)
- 참가자는 공개 전에는 자기 선택만 본다
- 공개 후 결과:
  - 항목별 표 수, 비율(투표자 수 대비, 정수 %로 반올림), 최다 득표 항목 강조(동점이면 모두)
  - 기타 응답: 내용 목록(같은 내용은 묶어 개수 표시)
  - 비익명이면 항목·기타 응답마다 고른 사람 이름(이름순)
- 공개 전 생성자 화면: "N/M명 투표"(M = 운동회 참가자 수)와 아직 안 한 사람 명단(이름, 결석이면 표시. 출석자 먼저, 이름순)
- 관리자 화면: 투표 제목, 상태, 투표 인원만. 응답과 이름은 보여 주지 않는다

## 4. 데이터

1단계에서 만든 테이블을 그대로 쓴다. 마이그레이션 `005_polls.sql`은 조회용 인덱스만 추가한다:

```sql
CREATE INDEX polls_event_idx ON polls (event_id);
CREATE INDEX poll_options_poll_idx ON poll_options (poll_id, sort_order);
CREATE INDEX poll_answers_poll_idx ON poll_answers (poll_id);
```

- `poll_voters`: 투표한 사람 한 명당 한 행(`unique(poll_id, participant_id)`). 투표 여부와 인원 집계에 쓴다
- `poll_answers`: 고른 항목마다 한 행(`option_id`) 또는 기타 한 행(`other_text`). `participant_id`는 항상 채운다

## 5. 화면

### 참가자 (`/e/:slug/...`)

- **홈 "🗳️ 투표" 카드**: 투표가 없으면 "아직 투표가 없어요". 있으면 진행 중 개수와, 안 한 진행 중 투표가 있으면 "투표할 게 N개 있어요" + `투표 보기`(→ `/polls`)
- **`GET /polls`**: 최신순 목록. 상태 배지(진행 중 / 마감 / 결과 공개), 진행 중이면 내 참여 여부(투표함 / 안 함)
- **`GET /polls/:id`**
  - `open`: 폼. 최대 선택 1이면 라디오, 2 이상이면 체크박스와 "최대 N개" 안내. 기타 허용이면 "기타" 입력칸. 익명이면 "익명 투표예요", 아니면 "이름이 공개되는 투표예요"를 표시. 이미 투표했으면 내 선택이 체크되어 있고 버튼은 `다시 투표`
  - `closed`: "마감됐어요. 결과 공개를 기다려 주세요"와 내 선택
  - `revealed`: 결과(§3)와 내 선택 표시
- **`POST /polls/:id/vote`**: 성공하면 `/polls/:id`로 303. 검증 실패는 같은 화면 400과 메시지. 마감·공개된 투표면 400 `마감된 투표입니다`

### 생성자 (`/e/:slug/manage/polls`, 관리 메뉴에 "투표" 추가)

- **목록**: 투표마다 제목, 상태, "N/M명 투표", 상세 링크. 아래에 새 투표 만들기 폼(항목은 한 줄에 하나씩 쓰는 텍스트 영역)
- **상세 `GET /manage/polls/:id`**: 설정 요약, 상태 전환 버튼(`마감` / `다시 열기` / `결과 공개`), 공개 전에는 안 한 사람 명단, 공개 후에는 결과. 투표자가 0명이고 공개 전이면 수정 폼. 삭제 폼(확인 문구)
- POST: `/manage/polls`(만들기), `/manage/polls/:id/edit`, `/manage/polls/:id/status`(`status=closed|open|revealed`), `/manage/polls/:id/delete`. 성공은 302, 검증 실패는 같은 화면 400과 메시지

### 플랫폼 관리자 (`/admin/events/:id`)

- "투표" 칸: 제목, 상태, 투표 인원 표. 응답·이름 없음

## 6. 서비스 구성

`src/services/polls.js`:

- `createPoll(eventId, input)`, `updatePoll(eventId, pollId, input)`, `deletePoll(eventId, pollId, confirm)`
- `setStatus(eventId, pollId, status)` — 허용 전환만(`open→closed`, `closed→open`, `closed→revealed`)
- `listForParticipant(eventId, participantId)`, `listForCreator(eventId)`, `listForAdmin(eventId)`
- `getForParticipant(eventId, pollId, participantId)` — 투표 정보, 항목, 내 선택, `revealed`일 때만 결과
- `getForCreator(eventId, pollId)` — 투표 정보, 항목, 인원, 공개 전 안 한 사람 명단, `revealed`일 때만 결과
- `vote(eventId, pollId, participantId, input)`
- `homeSummary(eventId, participantId)` — 진행 중 개수, 안 한 진행 중 개수
- 결과 계산은 순수 함수 `tally(poll, options, answers)`로 분리해 단위 테스트한다

모든 함수는 앞 단계 규칙(id 검증, `event_id` 범위, `ValidationError`, 잘못된 형식의 id는 `null`/`false`)을 따른다.

## 7. 동시성

- 투표, 다시 투표, 상태 전환, 수정, 삭제는 `db.tx` 안에서 투표 행을 `SELECT ... FOR UPDATE`로 잠그고(그 운동회 소속인지 함께 확인) 상태를 다시 확인한다
- 따라서 마감과 동시에 들어온 투표는 마감 전이면 반영되고 마감 후면 `마감된 투표입니다`로 거부된다
- 수정은 같은 잠금 안에서 투표자 0명을 확인하므로, 첫 투표와 수정이 엇갈려도 투표된 항목이 바뀌지 않는다

## 8. 에러 처리

- 잘못된 입력(제목·항목·개수·기타): 400과 메시지
- 허용되지 않는 상태 전환, 투표자가 있는 투표 수정, 마감된 투표에 투표: 400과 메시지
- 다른 운동회의 투표 id나 없는 id: 404

## 9. 테스트

- `tally` 단위 테스트: 비율 반올림, 동점 최다, 기타 묶기, 익명이면 이름 없음, 투표자 0명
- 서비스: 만들기 검증(항목 수·중복·최대 선택 수), 상태 전환 허용·거부, 수정은 투표자 0명일 때만, 투표 검증(다른 투표 항목, 개수 초과, 기타 비허용, 빈 기타), 다시 투표가 이전 응답을 대체, 마감 후 투표 거부, 동시 투표·마감(`Promise.all`)
- 비공개: 공개 전 참가자·생성자 응답(HTML)에 득표와 다른 사람 선택이 없음, 익명 투표는 공개 후에도 이름이 없음, 비익명은 공개 후 이름이 있음, 관리자 화면에 응답·이름 없음
- 라우트: 참가자 목록·상세·투표, 생성자 만들기·상태 전환·수정·삭제(확인 문구), 일반 참가자의 생성자 기능 접근 차단, 다른 운동회 투표 404
- 홈 카드: 투표 없음 / 안 한 투표 개수

## 10. 범위 밖(4단계)

- 마감 시각 예약(자동 마감)
- 순위·점수 투표
- 투표별 대상자 제한, 팀 단위 투표
- 결과 공개 연출 애니메이션
