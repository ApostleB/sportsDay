# 명량운동회 플랫폼: 2단계(팀 뽑기) 설계

- 작성일: 2026-10-12
- 상태: 사용자 검토 대기
- 선행: `2026-10-11-sportsday-foundation-design.md`(1단계). 이 문서에 없는 규칙(인증, 세션, 에러 처리, 디자인 시스템)은 1단계 스펙을 따른다

## 0. 목표와 확정된 요구사항

생성자가 참가자를 그룹으로 묶고 팀을 설정한 뒤, 참가자가 각자 자기 폰에서 두근두근한 연출과 함께 팀을 뽑는다.

사용자가 확정한 내용:

- 생성자는 참가자를 **그룹으로만** 묶는다. 같은 그룹 사람은 서로 다른 팀으로 흩어진다
- 생성자가 팀 수, 팀 이름, 팀 색을 정한다. 기본값은 레드·블루·그린·옐로우 4팀이다
- 생성자가 팀마다 팀장을 지정한다
- 뽑기는 참가자가 **자기 폰에서** 하고, 아직 뽑지 않은 사람은 생성자가 **대신 뽑아** 줄 수 있다
- 결과는 **미리 봉투 방식**: 생성자가 "뽑기 시작"을 누르는 순간 출석자 전원의 팀을 한 번에 정해 숨겨 두고, 뽑기는 봉투를 여는 행위다
- 뽑은 결과는 **즉시 모두에게** 보인다(새로고침 시)
- 생성자는 뽑기와 별개로 참가자를 팀에 **수동 배치하거나 옮길** 수 있고, 플랫폼 관리자도 생성자 화면에서 같은 일을 한다
- 폴링 없음. 모든 화면은 접속·새로고침 시점의 상태를 보여 준다

## 1. 뽑기 상태와 흐름

운동회의 뽑기 상태는 `events.draw_open` 하나로 표현한다.

| 상태 | `draw_open` | 가능한 일 |
|---|---|---|
| 준비 | `false` | 팀 설정, 그룹 편집, 참가자 그룹 지정 |
| 진행 | `true` | 봉투 열기(본인/대리), 수동 이동, 초기화 |

흐름:

1. **준비**: 생성자가 그룹을 만들고 참가자를 그룹에 넣는다. 팀을 설정하고 팀장을 지정한다
2. **시작**: 생성자가 "뽑기 시작"을 누르면 6절의 배정 알고리즘으로 출석자 전원의 팀을 정해 `participants.team_id`에 저장하고 `draw_open=true`로 바꾼다. 팀장은 자기 팀에 고정되고 즉시 공개된다(`draw_results.method='leader'`)
3. **뽑기**: 참가자가 봉투를 열면 `draw_results`에 행이 생기고 그때부터 결과가 보인다
4. **초기화**: 생성자가 확인 문구 `초기화`(앞뒤 공백 무시)를 입력하면 `participants.team_id`를 모두 NULL로, `draw_results`를 모두 삭제하고 `draw_open=false`로 되돌린다

진행 상태에서는 팀 설정과 그룹 편집, 참가자 그룹 변경이 잠긴다. 바꾸려면 초기화 후 다시 시작한다.

### 시작 조건

다음 중 하나라도 어기면 시작하지 않고 뽑기 진행 화면에 메시지를 보여 준다.

- 팀이 2개 이상
- 출석 참가자가 팀 수 이상
- 지정된 팀장은 모두 출석 상태이고, 한 사람이 두 팀의 팀장일 수 없다(팀장 미지정 팀은 허용)

## 2. 데이터

1단계에서 만든 테이블을 쓴다.

- `events.draw_open`: 뽑기 진행 여부
- `groups(event_id, name, sort_order)`: 그룹. 참가자의 소속은 `participants.group_id`
- `teams(event_id, name, color, leader_participant_id, sort_order)`: 팀
- `participants.team_id`: 봉투 속 배정. **공개 전에는 어떤 화면과 응답에도 노출하지 않는다**
- `draw_results(event_id, participant_id unique, team_id, drawn_at)`: 공개 기록. 화면에 보이는 팀 소속은 항상 이 테이블에서 읽는다

마이그레이션 `003_draw_method.sql`:

```sql
ALTER TABLE draw_results ADD COLUMN method text NOT NULL DEFAULT 'self'
  CHECK (method IN ('self', 'proxy', 'manual', 'leader'));
```

불변식: `draw_results`에 행이 있으면 그 `team_id`는 같은 참가자의 `participants.team_id`와 같다. 모든 쓰기 경로가 두 값을 한 트랜잭션에서 함께 바꾼다.

## 3. 생성자 화면 (`/e/:slug/manage/...`)

관리 메뉴(`creator-nav`)에 "팀 뽑기"를 추가한다. 세 화면 모두 `requireCreator`라서 플랫폼 관리자도 그대로 쓴다.

### `GET|POST /manage/teams` 팀 설정

- 팀 수 선택(2~8). 팀 수를 바꾸면 팀 행을 추가하거나 뒤에서부터 삭제한다. 새 팀은 팔레트에서 아직 안 쓴 색 중 첫 번째와 그 색 이름을 받는다
- 팀마다 이름(1~20자, 운동회 안에서 중복 불가), 색(팔레트 키, 팀끼리 중복 불가), 팀장(출석 참가자 선택 또는 없음)
- 한 폼에서 모든 팀을 저장한다
- 운동회를 만들 때 기본 4팀(레드·블루·그린·옐로우)을 함께 만든다. 이미 있는 운동회는 팀 설정 화면을 처음 열 때 팀이 없으면 기본 4팀을 만든다
- 진행 상태에서는 읽기 전용으로 보여 주고 POST는 400

### `GET|POST /manage/groups` 그룹

- 그룹 추가(이름 1~20자, 운동회 안에서 중복 불가), 이름 변경, 삭제(소속 참가자는 그룹 없음으로)
- 참가자 표: 이름, 출석, 그룹 선택. 한 폼으로 모든 참가자의 그룹을 저장한다
- 그룹이 없는 참가자는 6절에서 혼자인 그룹으로 취급한다
- 진행 상태에서는 읽기 전용, POST는 400

### `GET /manage/draw` 뽑기 진행

- 준비 상태: 시작 조건 점검 결과와 "뽑기 시작" 버튼
- 진행 상태:
  - 요약: 팀별 공개 인원, 아직 안 뽑은 인원
  - 참가자 표: 이름, 그룹, 상태(`안 뽑음 / 뽑음 / 대리 / 수동 / 팀장`), 공개된 팀
  - 안 뽑은 출석자에게 "대신 뽑기" 버튼(`POST /manage/draw/proxy/:participantId`)
  - 팀장이 아닌 모든 참가자에게 "팀 옮기기" 선택 + 저장(`POST /manage/draw/move/:participantId`)
  - "뽑기 초기화"(확인 문구 `초기화` 입력 필요, 앞뒤 공백은 무시)
- `POST /manage/draw/start`, `POST /manage/draw/reset`

생성자와 관리자도 아직 열리지 않은 봉투의 팀을 볼 수 없다. 이 화면도 `draw_results`만 읽는다.

## 4. 참가자 화면

### 홈 뽑기 카드와 배번표

- 준비 상태: "팀 뽑기 준비 중" 안내
- 진행 상태, 아직 안 뽑음: "팀 뽑기가 열렸어요"와 `뽑기` 버튼(`/draw`로 이동)
- 공개됨: 배번표가 팀 색으로 바뀌고 팀 배지(기호 + 팀 이름)와 팀장 이름을 표시. 카드는 "팀 현황 보기"(`/teams`)로 바뀐다
- 결석 상태이고 봉투가 없음: "결석으로 표시되어 있어요. 생성자에게 알려 주세요"

### `GET /e/:slug/draw` 뽑기 화면

- 목업 4번 화면(뽑기통 원판 + 팀 배지 + `뽑기!` 버튼)
- 이미 공개된 사람이 열면 연출 없이 결과를 보여 준다
- 준비 상태면 홈으로 리다이렉트

### `POST /e/:slug/draw` 봉투 열기

- 요청 헤더 `Accept: application/json`이면 JSON `{ team: { name, color, mark }, leaderName }`로 응답하고, 그 외에는 `/draw`로 303 리다이렉트(자바스크립트 없이도 동작)
- 이미 공개된 사람이 다시 보내면 같은 결과를 돌려준다(멱등)
- 준비 상태면 409(JSON) 또는 홈 리다이렉트
- 봉투가 없는 출석자(시작 후 출석으로 바뀌었거나 새로 들어온 사람)는 이 요청에서 6절의 늦은 배정으로 팀을 정한다
- 봉투가 없는 결석자는 400 "결석으로 표시되어 있어요"

### 연출 (`src/public/js/draw.js`)

1단계 디자인 토론에서 합의한 타임라인을 그대로 쓴다. 서버 응답을 받은 시점부터 진행하고, 대기 중에는 "팀 확인 중"을 표시한다.

| 시간 | 연출 |
|---|---|
| 0–600ms | 뽑기통이 `rotate(-3deg ↔ 3deg)`로 두 번 흔들림 |
| 600–2400ms | 팀 이름·기호가 차례로 지나가며 감속. 배경색은 고정 |
| 2400–2800ms | 결과 배번표가 `opacity 0→1, scale(.96)→1`로 등장하고 팀 색 적용 |

- 연출 중 44px 이상의 "결과 바로 보기" 버튼
- 결과 문구는 `aria-live="polite"`로 한 번 알림
- `prefers-reduced-motion: reduce`이면 즉시 결과
- 순환에 쓰는 팀 목록은 페이지에 렌더링된 운동회 팀 목록이고, 결과는 서버 응답에서만 온다

### `GET /e/:slug/teams` 팀 현황판

- 팀마다 팀 색 카드: 기호 + 팀 이름, 팀장(★ 표시), 공개된 팀원 이름(공개 순)
- 상단에 "아직 N명이 안 뽑았어요"
- 준비 상태면 "팀 뽑기 준비 중"

## 5. 수동 배치와 대리 뽑기

- **대리 뽑기**: 본인 봉투 열기와 같은 처리, `method='proxy'`. 늦은 배정도 같다
- **팀 옮기기**: 대상 참가자의 `team_id`를 바꾸고 `draw_results`를 upsert(`method='manual'`). 안 뽑은 사람을 옮기면 그 순간 공개된다. 결석자도 옮길 수 있다
- 팀장은 옮길 수 없다(팀장 변경은 초기화 후 팀 설정에서)
- 모두 진행 상태에서만 가능하고, 준비 상태면 400

## 6. 배정 알고리즘 (`src/services/draw-assign.js`)

DB에 의존하지 않는 순수 함수로 만들고, 난수 함수를 인자로 받아 시드 고정 테스트를 할 수 있게 한다.

### 시작 시 일괄 배정 `assignAll({ teams, members, random })`

- 입력: 팀 목록(각 팀의 팀장 참가자와 그 그룹), 배정할 참가자 목록(출석자 중 팀장 제외, 각자 `groupKey`). 그룹 없는 참가자의 `groupKey`는 `solo:<id>`
- 팀장은 자기 팀에 이미 한 자리를 차지한 것으로 센다(팀 인원과 그 그룹 인원 모두)
- 하드 조건 — **팀 인원 균형**: 팀 수 k, 팀장 포함 전체 인원 N일 때 각 팀 인원은 `floor(N/k)` 또는 `ceil(N/k)`
- 소프트 조건 — **그룹 분산**: 인원 g인 그룹은 어느 팀에도 `ceil(g/k)`명을 넘겨 들어가지 않는다
- 절차(한 번의 시도):
  1. 팀별 목표 인원을 정한다. `N mod k`개의 팀이 한 명 더 받으며, 어느 팀이 더 받을지는 무작위
  2. 그룹을 인원 많은 순으로(같으면 무작위) 처리하고, 그룹 안 멤버 순서는 섞는다
  3. 멤버마다 남은 자리가 있는 팀 중 이 그룹 인원이 가장 적은 팀들을 고르고, 그중 남은 자리가 가장 많은 팀들 사이에서 무작위로 고른다
- 시도의 벌점 = 모든 그룹·팀에 대해 `max(0, 그 팀의 그룹 인원 - ceil(g/k))`의 합
- 최대 200번 시도해 벌점 0이 나오면 바로 그것을, 아니면 벌점이 가장 작은 시도를 채택한다
- 출력: `Map<participantId, teamId>`

### 늦은 배정 `assignLate({ teams, member, random })`

- 입력: 팀별 현재 인원(봉투 포함 `participants.team_id` 기준, 출석 여부 무관)과 팀별 이 그룹 인원
- 전체 인원이 가장 적은 팀들 중에서 이 그룹 인원이 가장 적은 팀들을 고르고, 그중 무작위

## 7. 동시성과 비공개 보장

- 시작, 초기화, 봉투 열기(늦은 배정 포함), 대리 뽑기, 팀 옮기기, 팀 설정 저장, 그룹 저장은 모두 `tx` 안에서 `SELECT ... FROM events WHERE id=$1 FOR UPDATE`로 운동회 행을 먼저 잠근다. 그래서 동시에 눌러도 늦은 배정의 균형이 깨지지 않고, 시작과 그룹 편집이 엇갈리지 않는다
- 상태 검사(`draw_open`)는 잠근 뒤 다시 읽은 값으로 한다
- 봉투 비공개: 참가자·생성자·관리자 화면의 팀 정보 쿼리는 `draw_results`와 조인해서만 팀을 읽는다. `participants.team_id`를 직접 읽는 곳은 배정 서비스(`draw.js`)뿐이고, 결과는 공개된 사람의 것만 밖으로 나간다
- 참가자 삭제는 기존대로 CASCADE(`draw_results`) 처리한다. 팀장이 삭제되면 `leader_participant_id`가 NULL이 된다(기존 FK)

## 8. 서비스와 라우트 구성

- `src/services/teams.js`: 팔레트, 기본 팀 생성, 팀 목록, 팀 설정 저장(검증 포함)
- `src/services/groups.js`: 그룹 CRUD, 참가자 그룹 일괄 저장
- `src/services/draw-assign.js`: 6절 순수 함수
- `src/services/draw.js`: 시작 조건 점검, 시작, 초기화, 봉투 열기, 대리 뽑기, 팀 옮기기, 공개 현황 조회
- `src/routes/creator.js`에 팀·그룹·뽑기 관리 라우트, `src/routes/participant.js`에 `/draw`, `/teams`
- 모든 서비스는 1단계 규칙을 따른다: id는 `isId`로 검증, 모든 쿼리는 `event_id`로 범위 제한, 검증 실패는 `ValidationError`

## 9. 화면 디자인

- 1단계 디자인 시스템과 목업 3·4·5번 화면을 따른다
- 팀 배지는 색과 기호를 함께 쓴다(색만으로 구분하지 않음)
- 생성자 화면은 960px 폭, 표는 가로 스크롤 영역 안에 둔다
- 버튼·선택 상자 터치 영역 44px 이상, 뽑기 버튼 52px

## 10. 에러 처리

- 잠긴 상태에서의 편집 POST, 시작 조건 위반, 검증 실패: 같은 화면을 400으로 다시 렌더링하고 메시지 표시
- 없는 참가자·팀·그룹 id: 404
- 1단계와 같이 예기치 않은 에러는 500

## 11. 테스트

- `draw-assign` 단위 테스트(시드 고정 난수):
  - 여러 크기(참가자 2~40명, 팀 2~8개, 그룹 구성 다양, 팀장 유무)를 수백 번 돌려 팀 인원 균형이 항상 성립
  - 모든 그룹이 팀 수 이하이고 팀장이 없을 때 그룹 분산이 항상 성립(벌점 0)
  - 늦은 배정이 가장 적은 팀으로 가는지
- 서비스·라우트 통합 테스트:
  - 기본 4팀 생성, 팀 설정 검증(이름·색 중복, 팀장 결석, 한 사람 두 팀 팀장)
  - 시작 조건 위반 메시지, 시작 후 편집 잠금
  - 봉투 비공개: 시작 직후 현황판·관리 화면·참가자 홈 HTML에 안 뽑은 사람의 팀 이름이 나오지 않음
  - 봉투 열기 JSON/리다이렉트, 멱등성, 늦은 배정, 결석자 거부
  - 대리 뽑기, 팀 옮기기(공개 처리 포함), 팀장 이동 거부
  - 동시 봉투 열기 여러 건(`Promise.all`)에서 늦은 배정 균형 유지
  - 초기화 후 상태 원복, 확인 문구 불일치 거부
  - 관리자 세션으로 생성자 뽑기 화면 접근

## 12. 범위 밖(2단계)

- 실시간 갱신, 큰 화면 전용 발표 모드
- 팀 점수·경기 기록
- 시작 후 팀 설정 부분 변경(초기화 후 다시 시작으로 대신함)
