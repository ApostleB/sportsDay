# 디자인 토론 기록 (Claude Opus × Codex gpt-6-astra)

- 날짜: 2026-10-12
- 결과물: `docs/design/mockup.html`

## 브리프

### 서비스
지인 20~40명이 매년 여는 "제 n회 명량운동회"를 위한 모바일 웹. Express + EJS 서버 렌더링, CSS 한 파일(프레임워크 없음), 최소한의 바닐라 JS.
화면 3종: (1) 참가자 화면 (2) 운동회 생성자 관리 화면 (3) 플랫폼 관리자 화면.
1단계 화면: 메인(입장/운동회 만들기), 입장 폼(이름+4자리 PIN+인증코드), 참가자 홈(제목/일시/집합안내/공지/시간표 이미지), 생성자 대시보드·참가자 관리 표·공지·시간표 업로드, 관리자 목록·상세.
이후 단계: 팀 뽑기(두근두근 뽑기 애니메이션과 결과 공개), 마니또(개인 확인, 전체 오픈 후 순환 맵), 투표.
팀 기본 색: 레드, 블루, 그린, 옐로우.

### 지금 사용 중인 실제 포스터(제3회) 톤
- 큰 제목 "제 3회 명량운동회": 굵고 둥근 한글 디스플레이 서체. "제 3회"는 주황색(#FF8A3D 근처) 글자에 검은 외곽선, "명량운동회"는 흰 글자에 두꺼운 검은 외곽선(스티커/만화 느낌)
- 노란 형광펜 라벨 "집합 일시" + 날짜
- 시간표 표: 헤더는 하늘색(#3FB6F0 근처) 바탕 흰 글씨, 구분(준비/실외/점심/실내/퇴실) 열, 점심/정비 행은 하늘색 강조 줄. 테두리는 연한 살구색
- 하단에 주황 띠 배경, 우상단에 작은 운동회 메달 아이콘
- 전체적으로 밝고 장난스럽고 레트로한 학교 운동회 느낌. 준비물 칸이 "몸", "순발력", "악바리", "위장" 같은 유머

### 제약
- 모바일 우선(최대 폭 480px, 관리자 표 화면은 960px), 한국어
- Google Fonts만 사용 가능
- 접근성: 본문 대비 충분히, 터치 영역 44px 이상
- 다크모드는 필수 아님

### 원하는 것
"이쁜" 디자인. 지인들이 링크를 받아 열었을 때 "오 이거 우리 운동회 거다" 싶은 정체성.

## 1라운드: Codex 제안
1. **컨셉: “우리 운동회 포스터가 손안의 참가증으로.”**

실제 포스터의 **주황색 회차, 흰색 스티커 제목, 노란 형광펜, 하늘색 시간표**를 핵심 문법으로 사용합니다. 첫 화면에서 익숙함을 만들고, 정보 영역은 정돈된 종이 안내문처럼 구성합니다. 장식은 제목과 주요 행동에 집중합니다.

전체는 `max-width:480px; margin-inline:auto; padding:20px 16px 32px`. 간격은 `8 / 12 / 16 / 24 / 32px`, 관리자 표 화면만 `max-width:960px`.

2. **색 토큰**

| 토큰 | HEX | 용도 |
|---|---|---|
| `--paper` | `#FFF8EE` | 전체 배경 |
| `--surface` | `#FFFFFF` | 카드·입력 |
| `--ink` | `#24211E` | 본문·외곽선 |
| `--muted` | `#686058` | 보조 설명 |
| `--line` | `#E8CDB6` | 구분선·표 테두리 |
| `--orange` | `#FF8A3D` | 회차·주요 버튼 |
| `--sky` | `#3FB6F0` | 시간표·장식 |
| `--marker` | `#FFE66B` | 집합 일시 라벨 |
| `--focus` | `#175CD3` | 포커스 |
| `--danger` | `#B42318` | 오류·삭제 |
| `--team-red` | `#C93636` | 레드팀 |
| `--team-blue` | `#245BC7` | 블루팀 |
| `--team-green` | `#237448` | 그린팀 |
| `--team-yellow` | `#F4D34E` | 옐로우팀 |

주황·하늘·노랑 위에는 `--ink` 글씨를 씁니다. 포스터의 하늘색+흰색 조합은 작은 표 글씨에 그대로 적용하지 않습니다. 팀 배지는 레드·블루·그린에 흰 글씨, 옐로우에 검정 글씨를 사용합니다.

3. **서체**

- 제목: [Jua](https://fonts.google.com/specimen/Jua), `400`. 메인 제목 `clamp(34px,9vw,44px)/1.15`, 섹션 제목 `22px/1.3`.
- UI·본문: [Noto Sans KR](https://fonts.google.com/noto/specimen/Noto+Sans+KR), `400/500/700`. 본문 `16px/1.6`, 라벨 `14px/1.4`, 보조 `13px/1.5`.
- 시간·인원수: `font-variant-numeric:tabular-nums`.
- 스티커 제목은 `paint-order:stroke fill; -webkit-text-stroke:3px var(--ink)`와 `text-shadow:2px 3px 0 var(--ink)`. 외곽선은 큰 행사 제목에만 적용합니다.

4. **핵심 컴포넌트**

- **카드:** 흰 배경, `border:1px solid var(--line); border-radius:16px; padding:20px`. 집합 안내 카드만 `border:2px solid var(--ink); box-shadow:3px 4px 0 var(--ink)`.
- **버튼:** `min-height:48px; padding:12px 20px; border:2px solid var(--ink); border-radius:12px; font-weight:700`. 주요 버튼은 주황색+`box-shadow:0 3px 0 var(--ink)`. 눌림은 `translateY(2px)`와 그림자 축소. 보조 버튼은 흰색.
- **입력:** `height:52px; width:100%; border:1.5px solid var(--muted); border-radius:10px; padding:12px 14px; font-size:16px`. 라벨은 위에 상시 표시. 오류는 붉은 테두리와 구체적인 문장으로 안내합니다.
- **표:** `font-size:14px; border-collapse:collapse`, 셀 `padding:12px`, 행 높이 최소 `48px`. 시간표 헤더는 하늘색, 휴식 행은 `#E7F5FD`. 관리 표는 수평 스크롤과 이름 열 고정, 행별 메뉴 터치 영역 `44px`.
- **배지:** `padding:4px 10px; border-radius:999px; font-size:13px; font-weight:700`. 팀 이름과 서로 다른 기호를 함께 표시합니다.
- **헤더:** `min-height:60px`, 좌측 작은 행사명, 우측 계정 버튼. 하단 `1px` 살구색 선. 운영 화면에는 “운동회 관리” 또는 “플랫폼 관리”를 명시합니다.
- **공통 포커스:** `outline:3px solid var(--focus); outline-offset:3px`.

5. **참가자 홈·입장 화면**

**참가자 홈:**  
작은 헤더 → 스티커 제목과 `32px` 메달 → 집합 안내 카드 → 중요 공지 → 시간표 → 준비물 순서입니다. 첫 화면 안에서 행사명·날짜·집합 장소를 확인하게 합니다.

집합 안내는 노란 라벨 아래 날짜를 `24px/1.3`, 장소를 `18px`로 표시합니다. 시간표 이미지는 `width:100%; height:auto`, 원본 확대 링크와 핵심 일정의 텍스트 요약을 제공합니다. 준비물은 “몸·순발력·악바리·위장”을 작은 칩으로 표현합니다. 이후 팀 뽑기·마니또·투표가 열리면 집합 안내 다음에 참여 카드를 배치합니다.

**입장:**  
상단 행사 제목 → “참가자 입장” 카드 → 이름·4자리 PIN·인증코드 → 전체 폭 “운동회 입장하기” 버튼. 필드 간격 `20px`, 카드 위아래 `24px`. PIN은 쪼개진 네 칸 대신 단일 `type="password"` 입력에 `inputmode="numeric"; maxlength="4"`를 사용합니다. 인증코드는 붙여넣기를 허용하고 안내 문구를 붙입니다.

서비스 메인은 같은 제목 문법 아래 “입장하기”를 주 버튼, “운동회 만들기”를 보조 버튼으로 둡니다.

6. **팀 뽑기·마니또로 이어지는 연출**

공통 모티프는 **접힌 종이 참가증의 공개**입니다. 버튼 반응 `120ms`, 카드 등장 `180ms`, 결과 공개 `350ms cubic-bezier(.2,.8,.2,1)`. `transform`과 `opacity` 중심으로 구현합니다.

팀 뽑기는 카드가 `rotate(-3deg ↔ 3deg)`로 두 번 흔들린 뒤 팀 색과 이름을 공개하며 전체 연출은 `1.2초` 이내입니다. 마니또는 봉투를 눌러 개인 카드를 펼칩니다. 전체 공개 후 순환 맵은 모바일에서 세로 연결 목록, 넓은 화면에서 원형 배치를 사용합니다.

서버가 확정한 결과를 연출하고 재접속 시 즉시 보여줍니다. `prefers-reduced-motion:reduce`에서는 흔들림 없이 공개합니다. 개인 확인 전에는 이름을 화면에 노출하지 않습니다.

7. **피해야 할 것**

모든 카드의 두꺼운 검정 그림자, 반복되는 기울임, 상시 색종이 애니메이션, 작은 외곽선 글씨, 색으로만 구별하는 팀, 이미지로만 제공하는 일정, 관리 표의 과도한 장식은 피합니다.

Claude Opus와의 합의 기준은 **“포스터에서 가져온 제목·색·라벨은 유지하고, 장식의 강도는 화면의 정보량에 맞춘다”**로 제안합니다.
## 1라운드: Claude Opus 응답

큰 방향("포스터 문법 유지, 장식 강도는 정보량에 맞춘다")과 색 토큰, 팀 색 대비 보정, 버튼·입력 크기, 포커스, reduced-motion 처리에 동의한다. 아래는 이견과 추가 제안이다.

1. **"참가증"을 "배번표(러닝 비브)"로 구체화하자.** 참가자 홈 상단에 내 이름이 크게 적힌 배번표 카드(상단 모서리 핀 구멍 두 개, 회차 번호, 참가 번호)를 둔다. 팀 뽑기 전에는 흰 비브, 뽑기 후에는 팀 색 비브로 바뀐다. 운동회 정체성과 1~3단계 기능이 한 오브젝트로 이어진다.

2. **팀 뽑기 연출 1.2초는 너무 짧다.** 요구사항이 "두근두근하게 결과를 본다"이다. 3단계로 제안한다. (a) 탭하면 뽑기통이 흔들림 0.8초 (b) 팀 색이 빠르게 순환하다 점점 느려지는 룰렛 약 2초 + 심장박동 스케일 펄스 (c) 결과 비브가 팝 하고 등장 0.4초. 합계 3초 안팎, "건너뛰기" 버튼 제공, reduced-motion이면 바로 결과. 다시 접속하면 연출 없이 결과.

3. **텍스트 시간표 요약과 준비물 칩은 뺀다.** 1단계 데이터에는 시간표가 이미지로만 존재한다. 대신 이미지를 탭하면 전체 화면 보기, 캡션 표시. 접근성은 alt 텍스트(캡션)로 보완.

4. **제목 스티커 외곽선 구현.** `-webkit-text-stroke`는 글리프 안쪽을 깎아 Jua 같은 둥근 서체가 얇아진다. `paint-order`는 HTML 텍스트에서 브라우저 지원이 고르지 않다. `data-text` 의사 요소를 뒤에 겹쳐 외곽선만 그리는 2겹 방식(뒤: stroke 8px ink, 앞: fill)으로 하자. 오프셋 그림자는 뒤 레이어에만.

5. **서체.** 제목 Jua에 동의. 단 포스터의 "명량운동회"는 매우 굵다. Jua 단독으로 부족하면 대안으로 Do Hyeon 비교. 숫자 회차("제 3회")는 같은 서체로 주황.

6. **포스터의 하단 주황 띠와 하늘색 줄무늬를 레이아웃 장식으로.** 페이지 하단에 주황 띠(footer), 섹션 제목 왼쪽에 하늘색 짧은 바. 카드는 기본 얇은 테두리, 중요한 카드(집합 안내, 내 비브)만 잉크 테두리+오프셋 그림자.

7. **헤더는 단순하게.** 계정 개념이 없다. 상단 바에는 "제3회 명량운동회" 축약명과 우측 "내 이름" 칩(누르면 나가기). 생성자에게는 우측에 "관리" 버튼.

8. **관리 화면은 같은 토큰을 쓰되 스티커 장식 0.** 흰 카드, 얇은 선, 하늘색 표 헤더만.

## 2라운드: Codex 응답과 합의안
1. **부분동의 — 참가증을 비브로 구체화.** 이름과 팀 결과를 한 카드에 담는 방향이 좋습니다. 다만 큰 비브가 집합 정보를 밀어내지 않도록 높이는 콘텐츠에 따라 늘어나되 기본 `136px`로 잡습니다. 참가 번호는 실제로 부여된 경우만 표시하고, 팀 색은 카드 전체보다 상단 띠와 배지에 적용해 이름의 가독성을 유지합니다.

2. **부분동의 — 긴장감을 위한 연출 확대.** 1.2초보다 긴 연출에는 동의하지만, 제안한 구간 합계는 3.2초입니다. 빠른 색 순환과 심장박동을 동시에 넣으면 산만합니다. 총 `2.8초`로 조정하고, 색 순환 대신 네 팀 이름이 차례로 지나가며 감속하도록 합니다. 건너뛰기와 재접속 즉시 공개에 동의합니다.

3. **부분동의 — 준비물 칩 제외, 텍스트 일정은 유지.** 실제 데이터가 없는 준비물을 고정 노출하면 안 됩니다. 그러나 캡션과 짧은 alt만으로 시간표 이미지의 정보를 대체할 수는 없습니다. 업로드 시 **‘시간표 텍스트 설명’ textarea 하나**를 추가해 시간·활동·장소를 입력하게 합니다. 별도 일정 데이터 모델 없이도 접근성을 확보할 수 있습니다.

4. **부분동의 — 외곽선은 뒤 레이어로 분리.** 앞쪽 글자의 두께를 보존하는 방식에 동의합니다. 다만 `8px` 외곽선은 모바일에서 글자 사이를 메울 수 있어 `6px`, 그림자는 `2px 3px 0`으로 줄입니다. `data-text` 의사 요소 대신 `aria-hidden="true"`인 장식용 span을 겹쳐 제목이 중복 낭독되지 않게 합니다.

5. **동의 — Jua를 기본으로 확정.** 회차도 같은 서체와 주황색을 사용합니다. 초기 구현은 Jua 하나로 통일하고, Do Hyeon 추가 로딩이나 화면별 혼용은 하지 않습니다. 굵기는 외곽선으로 보완합니다.

6. **부분동의 — 포스터 장식의 제한적 확장.** 하단 주황 띠는 참가자 화면에 `8px` 높이로, 섹션의 하늘색 바는 `4×20px`로 적용합니다. 검정 그림자가 연속으로 경쟁하지 않도록 비브만 오프셋 그림자를 사용하고, 집합 안내는 검정 테두리와 노란 라벨로 강조합니다.

7. **부분동의 — 계정 버튼 제거.** 이름 칩은 참가자 식별에 적합하지만, 누르는 즉시 나가기는 예상하기 어렵습니다. 이름 칩을 누르면 명시적인 **‘나가기’ 버튼**이 펼쳐지게 합니다. 생성자는 ‘관리’ 링크를 별도로 제공하고 모든 조작 영역은 `44px` 이상으로 맞춥니다.

8. **동의 — 운영 화면의 장식 최소화.** 같은 색과 서체를 쓰되 스티커 제목·핀 구멍·오프셋 그림자는 제외합니다. 하늘색 표 헤더에는 진한 글씨를 사용하고, 삭제 같은 위험 행동만 붉게 표시합니다.

### 비브 카드 구조

흰 카드에 `min-height:136px; padding:16px; border:2px solid var(--ink); border-radius:16px; box-shadow:3px 4px 0 var(--ink)`.

### 팀 뽑기 연출 타임라인

서버 결과를 받은 시점부터 진행하며, 대기 중에는 정적인 ‘팀 확인 중’을 표시합니다.

| 시간 | 연출 |
|---|---|
| `0–600ms` | 종이 뽑기통이 `rotate(-3deg ↔ 3deg)`로 두 번 흔들림 |
| `600–2400ms` | 팀 이름·기호가 이동하며 점차 감속. 배경색은 고정 |
| `2400–2800ms` | 확정 비브가 `opacity:0→1; scale(.96)→1`로 등장하고 팀 색 적용 |

연출 중 `44px` 이상의 ‘결과 바로 보기’를 제공합니다. 결과 문구는 `aria-live="polite"`로 한 번 알립니다. 재접속과 `prefers-reduced-motion:reduce`에서는 즉시 결과를 표시합니다.
